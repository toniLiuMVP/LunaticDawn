[ 1. 本站的著作權合規哲學 ]

1.1 不公開創作性表現

本站不公開下列著作權保護內容:

  • 原版完整遊戲 EXE / ROM / 完整資料檔(玩家自備)
  • 遊戲內美術 / 角色立繪 / 場景圖
  • 遊戲內配樂(原 BGM 為玩家自備光碟 / Steam 安裝後的資料,本站不打包)
  • 遊戲內劇情對白原文
  • 攻略書 narrative 段落(本站只引用結構性事實,必要時少量引用,是否合理依個案判斷)
  • 第三方 PDF / docx / 截圖檔

⚠ 注意例外:本站散布少數修改過主程式的檔案與相關登錄檔(多數含免光碟啟動;另有相容性修正、略過已停止服務的登入驗證,或 ME 版遊玩及出現試玩版的問題解決),這些主程式內嵌的圖像(多為按鈕與工具列,俠客遊 IV 另含標題圖、網頁範本預覽圖與少量角色圖)與遊戲內文字(含對白;前途道標的主程式含整套遊戲文字)會隨主程式一起散布。範圍與下架承諾詳見 §8 fan preservation patched EXE 特別說明。

1.2 公開事實層

本站公開的是依各國著作權法不受保護的事實層內容:

  • 🇹🇼 台灣著作權法 §10-1:著作權保護僅及於表達，不及於其所表達之思想、程序、製程、系統、操作方法、概念、原理、發現
  • 🇹🇼 台灣著作權法 §9 第 1 項第 3 款:通用之符號、名詞、公式、數表、表格等不得為著作權之標的
  • 🇯🇵 日本著作権法 §2 第 1 項 第 1 號:創作性要件(事實 / 單純整理 ≠ 創作)
  • 🇯🇵 日本著作権法 §12-2:資料庫只保護創意性編排
  • 🇺🇸 17 USC §102(b):保護不及於構想、程序、過程、系統、操作方法、概念、原理、發現
  • 🇺🇸 Feist v. Rural Telephone (1991):事實本身不受著作權保護;事實的選擇與編排若欠缺最低限度的創意,亦不受保護
  • 🇺🇸 Sega v. Accolade (1992):為取得互通所需資訊而反組譯,可構成 fair use(個案判斷)

[ 2. 著作權異議流程 ]

2.1 必要資訊

寄信至 luntic.dawn@gmail.com 時請包含:

  1. 具體頁面 URL(本站哪一頁 / 哪一段)
  2. 你是著作權持有人或代理人(如:「我是青衫,某某 攻略原作者」/「我是 ARTDINK 代理人,代表 ARTDINK 主張權利」/ 「我是 某某 修改器原作者 kkt_zzz」)
  3. 你希望本站做什麼:
    • (a) 撤除該內容
    • (b) 變更 attribution(改名 / 加 link / 改說明)
    • (c) 要求加 disclaimer / 補充說明
    • (d) 其他
  4. 你的聯絡方式(toni 回覆用,本站不公開)

2.2 toni 的回應時程

  • 📨 收信後 7 天內 人工回覆(toni 為單人營運,非 24/7 客服)
  • 🛠 確認異議成立後 3 天內 修補 / 撤除內容
  • 📝 修補完成後寄信告知你,並提供 GitHub commit URL 證明

2.3 toni 不會爭辯

本站尊重原作者意願:

  • 你說撤就撤,不會問「你能不能改個說法」(雖然 fair use 法律上可能成立,但尊重你的意願優先)
  • 不會要求你提供詳細法律論證(信任你的身份聲明)
  • 不會引用 fair use 條款回駁(除非異議涉及惡意冒名，詳見 2.4)

2.4 例外:惡意冒名情況

若收到的異議信件明顯為冒名(例如有人冒充 ARTDINK 法務代表),toni 會:

  1. 要求進一步證明身份(公司信頭 / 律師資格 / 等)
  2. 必要時延後處理直到身份確認
  3. 不會單因匿名 / 不完整的異議信件就撤除合法內容

[ 4. 反通知 / Counter-Notice ]

8.5 可主張的依據與其限制

以下是本站能主張的依據,每一條都有適用限制,不代表散布修改檔一定合法。

  • 🇹🇼 台灣著作權法第 65 條(合理使用)：個案判斷,非營利與文化保存是有利因素,但不保證成立。第 80-2 條第 3 項第 8 款(還原工程)的例外,依主管機關認定要點第十二點,限於為達到另行創作之電腦程式與其他電腦程式間的相容性所做的還原工程,不當然涵蓋散布修改後的主程式
  • 🇯🇵 日本著作権法第 47-3 條第 1 項及第 47-6 條第 1 項第 6 號：程式複製物的所有人為在電腦上使用,在必要範圍內自行複製或改作,不當然允許散布給他人
  • 🇺🇸 17 USC §107(fair use)與 Sega v. Accolade(1992)：支持為互通性而逆向工程的主張(個案判斷);§1201(f) 限於獨立創作程式的互通;只有在單純為實現該互通、且不構成侵權或違反其他法律時,才可能容許把取得的資訊或必要技術方法提供他人,因此不當然正當化散布免光碟工具或修改後的主程式
